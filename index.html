关于我

我是杨植，北京理工大学自动化学院人工智能专业硕士研究生，预计于 2027 年 6 月毕业。目前在腾讯云参与 Octop 开源 Agent 平台的核心研发，负责上下文管理、长期记忆与多智能体协作。此前，我在香港城市大学获得计算机理学硕士学位。

我关注长程任务中的记忆与决策：当任务跨越多轮交互、多个会话，甚至需要在物理环境中持续行动时，智能体如何记住已经发生的事、更新对当前状态的判断，并据此选择下一步行动？这个问题贯穿了我的系统开发与具身导航研究。

在 Agent 长期记忆（Agent Memory）方面，我设计和实现了 OctopMemory，保留原始证据及其时间、来源和状态变化，支持跨会话检索、信息更新与冲突核验。我也关注上下文工程（Context Engineering）：根据当前任务组织模型需要的信息，让工具按需加载、历史记录能够回查，并让多个 Agent 在独立上下文中协作。这些工作既需要验证回答是否正确，也需要考虑上下文开销与执行延迟。

在具身智能（Embodied AI）方面，我研究零样本目标导航中的探索策略、空间记忆与多智能体推理。第一作者论文 InfoNav 被 NeurIPS 2026 主会接收，将语义相关性与信息增益结合，用于判断下一步应该去哪里寻找目标。我希望进一步探索，智能体如何把持续获得的观测和交互经验，转化为后续行动中可利用的记忆。

欢迎交流 Agent 长期记忆、上下文工程、空间记忆与长程决策，也欢迎讨论相关评测和开源实现。可以通过邮件联系我。

开源与工程

OctopMemory Agent 长期记忆

Octop 的长期记忆模块 · 核心设计与实现

我负责设计和实现 Octop 的长期记忆系统。系统保留原始证据、时间和信息变化记录，在回答时按问题查找相关历史；涉及跨会话推理或前后信息冲突时，再进一步读取和核对来源。

历史信息保存在模型之外，每次回答只加载当前需要的部分。我重点处理三个问题：过去的信息是否仍然有效、回答能否找到依据，以及检索过程会占用多少上下文。

Octop 上下文管理与多智能体协作

腾讯云开源 Agent 平台 · 核心贡献者

我参与上下文运行时研发，让工具定义按任务需要加载，将过长的工具输出保存为可回查的文件，并在长程任务中整理历史上下文。

在缓存优化中，我通过请求回放分析父 Agent 与子 Agent 的共享前缀，发现工具定义的插入和排序变化会影响缓存命中。固定工具排序、调整任务工具的位置后，在所测暖缓存场景中，端到端延迟从 6.5 秒降到 2.9 秒，约降低 55%。

我也实现了多专家协作与后台任务机制：各专家在独立上下文中检索和推理，再向协调 Agent 返回结论，避免把全部中间过程塞进主对话。
